# Spec-driven development on Power Platform with GitHub Copilot and Spec Kit

A complete, working example of AI agents building and changing a **Power Platform** solution from specifications:
a Dataverse data model, a Power Apps canvas app, a Copilot Studio agent and Power Automate flows. It uses
**GitHub Copilot** and **GitHub Spec Kit**. A **constitution** governs every change, a **three-layer harness**
checks it, and three **human gates** keep a person in charge.

> [!IMPORTANT]
> **A learning example for this seminar, not a template or production code.** Read it to understand the approach,
> then build your own. Don't copy the constitution, agents or scripts into a real project as they are: they were
> written for this demo app. The identity model (a typed email, no password) and the security role in the setup
> guide are for demo only and do not protect data. Run it only in a dedicated Developer environment.

The example app is **Timekeeper**, a timesheet app: employees log hours, managers approve them (in the app or from a
Teams card), and an assistant agent can log, submit and summarise time for the signed-in user.

```text
 you write             Copilot (Spec Kit)                     Power Platform
 ─────────             ──────────────────                     ──────────────
 requirement ──▶ /speckit-specify ──▶ spec.md ──▶ 👤 accept
                 /speckit-plan    ──▶ plan.md ──▶ 👤 approve
                 /speckit-tasks   ──▶ tasks.md
                 /speckit-implement
                   coordinator ─▶ implementor ─▶ canvas-authoring MCP ─▶ canvas app (live in Studio)
                        ▲               │       pac copilot push      ─▶ Copilot Studio agent
                        │               │       Dataverse Web API     ─▶ tables, flows, connection refs
                        └── verifier ◀──┘  (read-only, max 3 attempts per task)
                 run-harness.ps1: agent evals · Playwright UI + API contract · verifier verdicts
                                                                 ──▶ 👤 go/no-go, then you publish
```

## What's automated, and how

| Step | Tool | Where |
|---|---|---|
| Publisher, solution, tables, columns, lookups, seed data | Dataverse Web API with an `az` token | `scripts/setup-environment.ps1` |
| Connection references, environment variable, cloud flows | Dataverse Web API (`workflows` with `clientdata`) | `scripts/setup-environment.ps1`, `flows/*.json` |
| Canvas app screens and formulas | Canvas-authoring MCP server (`canvas-apps` plugin): `sync_canvas`, `compile_canvas` | `canvasapp/*.pa.yaml` |
| Agent instructions, tools, topics | Copilot Studio VS Code extension clone, then `pac copilot pull/push/publish` | `agents/Timekeeper/`, `scripts/sync-agent.ps1` |
| Agent tests (Layer 1) | Test sets written as `botcomponents`, run with `pac copilot-studio run-maker-evaluation-test-set` | `harness/layer1-agent-evals/`, `scripts/run-agent-evals.ps1` |
| UI and schema tests (Layer 2) | Playwright in the Power Apps web player, plus Dataverse Web API checks | `harness/layer2-playwright/` |
| Self-correction (Layer 3) | Coordinator, implementor and verifier agents | `.github/agents/`, `harness/layer3-self-correct/` |
| Go/no-go | Refuses unless every layer is green, then asks you | `scripts/publish-gate.ps1` |

Every command, API call and trap we hit is written down in **[`docs/automation-playbook.md`](docs/automation-playbook.md)**.

What still needs a person (marked 👤 everywhere): signing in, creating three connections, creating the empty agent
and cloning it once, creating the empty canvas app and adding its data sources and flows, the three human gates,
and saving and publishing the app.

## Get started

**[`docs/setup.md`](docs/setup.md)** takes you from an empty environment to a working app, step by step (about 45 minutes).
The same human steps are 👤 tasks in `specs/001-timekeeper-core/tasks.md`, so `/speckit-implement` stops at
each one and prints a `HUMAN GATE`.

Before you start, `.\scripts\test-repo.ps1` checks the repo offline in a few seconds: every Dataverse name the
app, agent, flows and tests use is created by the setup script, everything parses, and nothing private is committed.

Then try the Spec Kit loop yourself: paste the requirement in `prompts/002-live-requirement.md` into Copilot
and compare your result with `examples/002-vacation-balance/`.

## What to take away

Take the ideas, not the files. When you're ready to try this on your own app, start a new repo with
`specify init <name> --ai copilot --script ps` and write each piece for your own domain.

- **The constitution** (`.specify/memory/constitution.md`): see how it's structured: numbered principles, which ones
  can't be skipped, and a version history. Then write rules for your own domain, security model and responsible-AI needs.
- **Human gates**: decide which decisions only a person makes (here: accepting the spec, approving the plan, and
  publishing). Write them where every agent reads them, and make the agent stop and say so when it reaches one.
- **Coordinator, implementor and verifier** (`.github/agents/`): the agent that checks the work can't edit files, and
  the fix loop has a limit (3 attempts) before it hands over to a person.
- **The three-layer harness** (`harness/`): agent evaluations, UI and API tests, and verifier verdicts give the person
  at the go/no-go gate evidence to decide on, rather than an agent saying it's done.
- **The automation playbook** (`docs/automation-playbook.md`): what Power Platform lets you automate today, what still
  needs a person, and the traps we hit.

## Notes

- **Demo identity model**: users type their email on a sign-in panel, and there is no password. This lets one
  Microsoft account demo every persona. A production app needs Microsoft sign-in plus Dataverse security roles
  (Constitution V).
- Everything uses the publisher prefix `tk_`. To use another one, replace `tk_` across the repo before running setup.
- The flows and the agent evals use the *Central Standard Time* time zone for "this week". To change it, edit `flows/*.json`
  and pass `-TimeZone` to `scripts/run-agent-evals.ps1`.
- Versions verified: Spec Kit 1.2.0, pac CLI 2.13.1, Playwright 1.63, Dataverse Web API v9.2.
